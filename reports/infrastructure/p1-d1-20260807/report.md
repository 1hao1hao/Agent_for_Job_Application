# P1-D1 Engineering Delivery

## Scope

- Standard Okapi BM25 with a versioned offline index.
- FastAPI Query, Trace and asynchronous Evaluation Job endpoints.
- PostgreSQL request/trace/job/run persistence.
- Redis queue and independent Evaluation Worker.
- Docker Compose definition and GitHub Actions stack validation.

## BM25 Dev Ablation

Dataset `evalrag_v0.2`, split `dev`, 80 cases (60 answerable). Predictions were
generated by the actual Router/Retriever; no frozen-test labels were changed.

| Retriever | Recall@3 | Recall@5 | MRR | P50 ms | P95 ms |
|---|---:|---:|---:|---:|---:|
| Keyword | 73.33% | 80.56% | 85.97% | 6.990 | 10.701 |
| BM25 | 55.56% | 78.89% | 68.33% | 0.509 | 1.130 |
| Dense | 72.78% | 80.83% | 67.42% | 96.946 | 196.223 |
| BM25 + Dense RRF | 73.89% | 80.00% | 72.14% | 96.992 | 696.178 |

BM25 improved several multi-source cases but regressed semantic paraphrases. BM25 +
Dense slightly improved Recall@3 over Keyword but reduced Recall@5/MRR, so this task
does not replace the existing frozen P0 Hybrid configuration. Ten strategy-difference
cases are retained in the ablation artifact.

## Service Validation

The local host has no Docker daemon. Equivalent real adapters were therefore started as
local PostgreSQL 10.19 and Redis 7.2.7 processes:

1. FastAPI accepted a BM25 Query and returned an answered `RagResponse` with a valid Citation.
2. The Trace endpoint loaded the same request-level AgentTrace from PostgreSQL.
3. The Evaluation endpoint returned a queued job without running evaluation inline.
4. Redis delivered the job id to the independent Worker.
5. The Worker ran the actual Evaluation CLI and persisted `succeeded` plus `report_path`.
6. A new repository instance could still read the completed job.

Completed job evidence: [completed_job.json](completed_job.json).

## Docker Validation

`docker-compose 5.4.0 config --quiet` passed locally. Local `compose up` could not run because
`/var/run/docker.sock` does not exist and the account has no sudo access, so the same Compose
file was executed on a Docker-enabled GitHub runner.

The first CI run exposed a shared-volume copy-up race while API and Worker started together.
The fix separated Trace and Report volume ownership and set the shared index volume to
`nocopy`. The second run built all images, passed service healthchecks, completed Query/Trace
and asynchronous Evaluation Job flows, recorded four running services, and shut down cleanly.

Successful run: [P1 Service Integration #31167280941](https://github.com/1hao1hao/Agent_for_Job_Application/actions/runs/31167280941).
